# 灾厄模组内容全面分析报告

> 分析时间：2026-11-10 | 数据源：Calamity 官方 Wiki、微信官方文档、竞品核查

## 一、结论先行

**值得做，但不能按原版图鉴的方式一次做完。** 灾厄是泰拉瑞亚生态最大的增量内容，微信小程序端灾厄资料工具基本空窗，存在先发机会；但工程量是"再造半个图鉴"（物品 2000~3000+、Boss 30~48），且有一条体积硬约束（30MB 总包红线）。建议**轻量试水 → 数据验证 → 分期投入**。

## 二、为什么值得做

1. **受众真实且硬核**：灾厄是泰拉瑞亚第一大 mod（tModLoader 订阅量第一），"打完原版打灾厄"是主流路径，与现有用户重合度高，流量承接自然
2. **搜索需求高频**：灾厄 Boss 攻略、武器推荐、进度顺序、职业配装是社区高频查询（B站灾厄视频播放量普遍高）
3. **竞品空窗**：泰拉酒馆虽然也有微信小程序，但主打原版，其灾厄百科放在网页子站（zaie.jgbk.net）；微信生态内目前没有成型的灾厄资料小程序——**先发窗口存在**
4. **变现场景增量**：灾厄页面流量直接带来广告展示增量；如果未来做虚拟支付，"灾厄专区工具"也是功能解锁的候选权益

## 三、数据规模与硬约束

### 数据体量（多来源交叉估计）

| 项目 | 规模 | 对比原版图鉴（我们已做） |
|---|---|---|
| 新增物品 | 2000~3000+ | 原版全量约 7000 条 |
| Boss | 30~48（含迷你 Boss/事件 Boss） | 原版 20+ |
| 合成配方 | 5000+ | 原版约 4000 |
| 新机制 | 盗贼职业、怒气/肾上腺素、复仇/死亡模式 | — |

**工程量约为原版图鉴的 40%~60%**。

### 硬约束：30MB 总包红线

微信小程序所有分包合计不超过 30MB（单包/主包 2MB）。我们现状：主包约 1.95MB + 原版三卷图标约 6400 个 + 其他分包，估计已用 15~20MB。**灾厄 2000~3000 个图标原样打包必超限**，必须先做体积审计与策略：

- 灾厄图标为 32×32 像素风，png 压缩空间大（预计可压到 3~8KB/个）
- 灾厄卷独立分包并按内容拆 2~3 个分包
- 长尾条目可用通用像素图标兜底，旗舰条目（Boss/毕业装）才带原图

### 数据源现状（已核实）

| 来源 | 状态 |
|---|---|
| calamitymod.wiki.gg 英文版 | 官方 Wiki，数据最全；API 有 Cloudflare 防护，抓取管线需验证或绕行 |
| calamitymod.wiki.gg 中文版 | **覆盖不完整**（zh URL 被重定向回英文首页），不能像原版那样直接抓中文 |
| 灾厄汉化包 | GitHub 开源语言文件（hjson/json），物品名/工具提示的**权威中文翻译，结构化可程序化映射**——中文名的正确来源 |
| 泰拉酒馆灾厄子站 | 网页可参考，反爬 |

**实施口径**：英文数据抓 en wiki + 汉化包映射中文名，与原版 build-catalog 的管线思路一致，但多一道映射工序。

## 四、分阶段路线图

### 一期：灾厄专区试水（建议先做，约 1~2 次会话）

- **内容**：灾厄 Boss 进度顺序图（30~48 Boss 分阶段一图流）+ 每 Boss 攻略卡（召唤方式/阶段要点/关键掉落 3~5 个）+ 灾厄机制说明（盗贼职业、怒气/肾上腺素、复仇/死亡模式）+ 常见 FAQ
- **载体**：新建 pkg-calamity 分包（或先挂 pkgB-guide 分类），主包加"灾厄专区"入口
- **成本**：低（Boss 数量几十个，文案级内容，无图标依赖）
- **验证手段**：stats_daily 访问统计已就位——灾厄页面的访问量直接告诉你要不要投入二期

### 二期：灾厄物品精选（数据验证后）

- 300~500 条核心数据：各阶段毕业装、职业代表武器、关键饰品与材料
- 带图标（先做体积审计与压缩实验）
- 支持搜索与详情弹窗（复用图鉴组件体系）

### 三期：灾厄全图鉴（重度投入）

- 2000~3000 条全量 + 微光嬗变式联动（灾厄有自己的转化/合成网络）
- 前置条件：一期二期的访问数据支持 + 图标体积方案落地

## 五、风险清单

| 风险 | 等级 | 对策 |
|---|---|---|
| 体积超 30MB 上限 | 高 | 先体积审计；图标压缩+多分包+长尾降级 |
| 维护成本（灾厄持续更新） | 中 | 数据管线自动化（build-calamity 脚本化），版本 bump 机制沿用 |
| 版权感知（mod 内容商用化） | 中 | 灾厄内容保持免费+广告；不进付费墙；关于页标注"非官方粉丝工具" |
| 定位稀释（原版→原版+灾厄） | 低 | 独立专区隔离，原版体验不变；反而新增"灾厄"搜一搜关键词入口 |
| 中文译名准确性 | 中 | 以灾厄官方汉化包为准，词条上线前抽查（星力手环教训同样适用于灾厄） |

## 六、与现有体系的关系

- **架构复用**：图鉴三级加载、分卷缓存、分片存储、专题组件、搜索管线全部可复用，灾厄相当于"第四/五/六卷"
- **付费结合**：灾厄内容本身建议免费；虚拟支付上线后的通用权益（去广告、主题）自然覆盖灾厄页面
- **统计验证**：一期上线即有访问数据，决策有据可依

## 七、决策点

需要杨扬拍板的：① 是否按"一期试水"启动（建议是）② 灾厄专区入口形态（图鉴页内切换 vs 首页独立宫格）③ 一期 Boss 攻略卡的文案深度（速查卡 vs 详攻略）。
