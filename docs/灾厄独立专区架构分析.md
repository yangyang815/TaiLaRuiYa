# 灾厄独立专区架构分析（用户方案：原版/灾厄彻底分开 + 切换）

生成时间：2026-11-18
结论先行：**可行，而且比"混进现有板块"更干净，我支持按这个方向做。**但"切换"分两个层次，一期做 L1（独立专区，成本几乎不变），L2（全局模式切换）二期看数据再上。

---

## 一、你的想法拆成两个层次

**L1 独立专区（隔离层）——一期就做**
灾厄是自己的分包（pkg-cal）+ 自己的页面 + 自己的数据 + 自己的搜索，和原版内容**零共享内容**。"切换"= 从首页宫格进出专区。互相不干扰天然成立，主包和原版分包一行不改。

**L2 全局模式切换（体验层）——二期再定**
图鉴/搜索顶部"原版 ｜ 灾厄"分段开关，整个数据层按模式换源（连收藏、历史都跟着切）。体验更"像两个 app"，但要触碰所有数据热路径，回归面大。建议：一期专区先自闭环（专区内置搜索/物品浏览），如果数据显示灾厄用户高频使用，二期再升级为全局切换——架构上从 L1 升 L2 是顺滑的，因为数据层从第一天就带 mode 维度。

## 二、体积实测（2026-11-18，推翻了之前"15~20MB"的估计）

| 项 | 实测 | 上限 |
|---|---|---|
| 主包（不含 cloudfunctions） | **1962KB** | 2048KB（余量 86KB） |
| 三个图鉴分包 | 1702+1394+1287 = 4383KB | 单分包 2048KB |
| 其余分包（recipe/tool/guide） | 1444+155+150 = 1749KB | 同上 |
| **全项目上传体积** | **约 7.9MB** | **30MB（余量 22MB）** |

关键更正：scripts（12.8MB）和 docs 在 packOptions 里本就被忽略，不上传——所以之前"已用 15~20MB"的估计严重偏高，**体积余量比想象中充足得多**。

### 三阶段推演

| 阶段 | 增量 | 判定 |
|---|---|---|
| 一期（纯文案，Boss 卡+机制+FAQ） | <50KB，独立分包 pkg-cal | 零风险 |
| 二期（300~500 条精选 + 图标） | 图标约 1.5~2.5MB | 注意**单分包 2MB 上限**：webp 压缩（省 50%+）或拆 pkg-cal-1/2，总量无压力 |
| 三期（2000+ 条全量 + 图标） | 6~15MB，拆 3~4 个分包 | 总量 15~23MB < 30MB ✓，需提前规划压缩与分包划分 |

## 三、"互相不干扰"隔离清单（逐项落实方案）

| 维度 | 隔离方案 |
|---|---|
| 数据文件 | pkg-cal/data/* 独立文件，与原版 data/ 完全分离 |
| 缓存 | 独立命名空间 terr_calv_* + 独立版本号 cat-data-ver-cal（沿用原版分片缓存方案，不共用键） |
| 条目 ID | 灾厄条目 id 一律 cal_ 前缀 → 收藏/评论/成就/浏览记录零冲突 |
| 搜索 | 主搜索永不收录灾厄条目；专区内置搜索（一期做简版或二期做） |
| 统计 | 独立路由自动隔离，stats_daily 直接能看灾厄页访问量 |
| 主题 | 共享主题系统；彩蛋：灾厄模式可配专属"灾厄"主题色 |
| 广告/付费 | 共享组件，去广告权益全局生效，无冲突 |
| 下载体验 | pkg-cal 不配预下载，首次进专区有几秒分包下载，之后秒开（避免不玩灾厄的用户白耗流量） |

## 四、切换形态的 UX 建议（需要拍板）

- **推荐**：首页宫格常驻"灾厄专区"入口（子群体一眼可见，不用找开关），专区内部顶部显示"当前：灾厄模式"
- **备选**：首页顶部"原版 ｜ 灾厄"分段开关，切换整页宫格内容（可实现、成本低，但会隐藏原版功能，纯原版玩家可能困惑）
- 两者也可并存：宫格入口 + 专区内部模式标识

---

## 五、对一期明细的修订

- 唯一变化：页面与数据从 pkgB-guide 移入**独立分包 pkg-cal**（pages×3 + data×2 全部搬过去）
- 内容本身不变：26 张 Boss 卡 + 机制 4 页 + FAQ + verify 扩展
- 成本不变：仍是 1~2 次会话（分包配置多 10 分钟）
- 数据层从第一天带 mode 参数（为 L2 预留钩子，但一期不实现全局切换）

---

## 六、L2 全局切换的触发条件（二期决策标准）

1. 灾厄专区一期上线后 stats_daily 访问量达标（日访问 > 原版攻略页均值的 50%）
2. 二期灾厄物品数据就绪
3. 满足两条 → 升级全局切换（预估 +1~2 会话，需全量回归测试）
