# 使用统计使用说明（P2-1 轻量数据统计）

> 上线日期：2026-10-29 ｜ 原则：隐私最小化，只统计聚合访问量，不碰任何个人数据

## 一、统计了什么（全部为匿名聚合计数）

| 键格式 | 例子 | 含义 |
|---|---|---|
| `pv:页面路由` | `pv:pages/home/home` | 某页面被打开的次数 |
| `pv:路由?id=值` | `pv:pages/strategy/strategy?id=zenith` | 某篇内容（攻略/条目/视频）被看的次数 |
| `ev:事件` | `ev:search` / `ev:feedback` | 关键动作发生次数 |

**明确不采集**：openid、设备号、位置、搜索词（kw 参数被硬性排除）、任何用户输入内容。
**技术上无法反推个人**：数据只有"某天某页面共被访问几次"一种语义，没有任何用户维度。

## 二、怎么查看数据（运营必读）

> ⚠️ 入口说明：云开发控制台的**主入口在微信开发者工具**（顶部工具栏的「云开发」按钮），不在 mp.weixin.qq.com 后台的"开发管理"里。mp 后台的"开发管理"只有云开发的配置信息，没有数据库管理界面。

**标准查看路径**：

1. 微信开发者工具 → 顶部工具栏点「**云开发**」→ 打开云开发控制台
2. 左侧选「**数据库**」→ 找到 **stats_daily** 集合
3. 每条文档 = 某个自然日（东八区）+ 某个键的累计次数，字段：`d`（日期）、`k`（键）、`n`（次数）
4. 点 `n` 列排序（降序）→ 前面的就是最受欢迎的页面/攻略；顶部筛选框可以按 `d` 或 `k` 过滤

### 还没数据？三步排查

1. **trackPage 云函数部署了吗**：开发者工具左侧目录 → `cloudfunctions/trackPage` → 右键 →「上传并部署：云端安装依赖」。没部署的话客户端上报全部静默失败，数据永远是空的
2. **产生一条测试数据**：云开发控制台 → 「云函数」→ `trackPage` → 详情 → 「云端测试」→ 粘贴下面参数 → 点"运行"：
   ```json
   {
     "items": [
       { "k": "pv:pages/home/home", "n": 3 },
       { "k": "pv:pages/strategy/strategy?id=test", "n": 2 },
       { "k": "ev:search", "n": 1 }
     ]
   }
   ```
   返回 `{ ok: true, day: "…", accepted: 3 }` 即链路通；再回数据库看 stats_daily 就有 3 条记录了（stats_daily 集合会由云函数首次调用自动创建）
3. **线上真实数据要等发版**：统计代码是随版本下发的，未发版前只有开发者的测试数据。补充：微信官方自带「访问分析」在 mp.weixin.qq.com → 统计 → 访问分析 → 访问页面，有页面级 PV/UV/停留时长，现在就能看，两个数据源互补

### 运营决策示例

- 哪篇攻略 n 最高 → 它的相关内容优先更新、纠错优先核对
- 某页面 pv 很低 → 入口可能太深，考虑调首页宫格或快捷入口
- `ev:search` 高但攻略 pv 低 → 搜索结果可能没接住需求，检查搜索结果页到攻略的跳转
- 图鉴装载页 `pkg-cat-*` 已被排除，不会污染数据

## 三、技术实现（维护备忘）

- 客户端：`utils/track.js` + `app.js` 全局 Page 包装（onShow 自动计数，业务零侵入）
- 上报：本地聚合计数，累计 16 条或退后台时批量调用云函数 `trackPage`（每会话约 1 次请求）
- 失败自愈：上报失败暂存本地 `trackBuf`，下次启动恢复重报
- 服务端：`cloudfunctions/trackPage`，校验键格式（白名单参数 id/cat/cls/type/bvid）、服务端生成日期、`_.inc` 原子累加
- 集合 `stats_daily` 由云函数**自动创建**，无需手动建；权限保持默认（仅创建者可读写）即可，云函数不受客户端权限限制，客户端也读不到统计数据

## 四、新增埋点的方法

1. **页面**：无需任何代码（全局 Page 包装自动覆盖，含未来新增页面）
2. **内容参数**：页面路由带 `id/cat/cls/type/bvid` 参数即自动细分；新增其它参数需改 `track.js` 的 `PARAM_WL`（谨慎，勿加自由文本类参数）
3. **事件**：业务代码 `const track = require("../../utils/track"); track.event("事件名");`

## 五、运维注意

- **发版前**：云函数 `trackPage` 需在开发者工具中右键 → 上传并部署（云端安装依赖），一次性操作
- 数据量级：每天文档数 ≈ 当日活跃页面/内容数（几百内），一年几千条，无需清理
- 成本：每会话约 1 次云函数调用，远低于免费额度
- 若要彻底停用：删除 `app.js` 里的 Page 包装段落 + `trackPage` 云函数即可，其余页面代码无需动
